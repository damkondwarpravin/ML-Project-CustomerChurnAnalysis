# Customer Churn Analysis

An end-to-end exploratory data analysis and machine-learning project that investigates customer churn and compares classifiers for identifying customers who leave the bank.

## Project contents

- `customer-churn-analysis.ipynb` — reproducible analysis, visualizations, model comparison, and tuned-model evaluation.
- `data/CustomerChurnSampleData.csv` — 10,000-row input dataset.
- `CustomerChurn.zip` is a duplicate of the extracted CSV and is excluded from Git to avoid storing the same data twice.
- `results_df.csv` — baseline model metrics, generated by the notebook.
- `tuned_model_results.csv` — tuned random-forest metrics, generated by the notebook.
- `requirements.txt` — Python dependencies.

## Dataset and target

The target is `churn` (`1` means a customer left; `0` means the customer stayed). The analysis excludes `customer_id` from model features because it is an identifier, not a useful customer attribute. Categorical country and gender values are one-hot encoded; numeric fields are standardized in a scikit-learn pipeline.

## Key exploratory findings

In this sample, the overall churn rate is **20.37%**. Observed churn rates are higher in Germany (32.4%) than France (16.2%) or Spain (16.7%), and higher among female customers (25.1%) than male customers (16.5%). Churn also varies by age and number of products; the 60 customers with four products all churned, a small group that should be interpreted cautiously. These are descriptive associations in this dataset, not evidence that any characteristic causes churn.

## Modeling approach

The notebook uses a stratified 80/20 train/test split and compares logistic regression, a decision tree, and a random forest. It reports accuracy, precision, recall, and F1 so model selection is not based on accuracy alone despite the imbalanced target. Preprocessing is fitted within each estimator pipeline to avoid leaking test-fold information. A randomized cross-validation search selects a random-forest model using F1, after which the final model is evaluated once on the held-out test set.

With the fixed random seed in the notebook, the tuned random forest achieved **0.847 accuracy**, **0.628 precision**, **0.609 recall**, and **0.618 F1** for the churn class on the held-out test set. The untuned random forest baseline achieved a test F1 of **0.563**. These metrics illustrate the precision/recall trade-off and are specific to this sample and split.

## Run the project

From the project folder, create and activate a virtual environment, then install dependencies:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Open `customer-churn-analysis.ipynb` in Jupyter or VS Code and run all cells from top to bottom. The notebook reads the CSV using a path relative to the project folder and regenerates both results CSV files.

## Limitations

This is an educational analysis of a single sample dataset. The reported metrics depend on the sample, split, and decision threshold; they should not be treated as production performance estimates. Churn patterns are observational and do not establish causality.
